# T4 — Tenant Customizing

> **Duration:** ~25 minutes  
> **Role:** Regulator / Provider  
> **Prerequisite:** T1 Bootstrap completed (T4 is standalone — T2/T3 not required)

Extend US.Payroll with two Apex-specific benefits using a Level 2 regulation.
No modification of the core regulation needed.

---

## What You Will Learn

- Understand the L1/L2 regulation layer concept
- Create a company-specific `Apex.Payroll` regulation
- Add a pre-tax benefit with a statutory limit (§132(f) commuter transit — reduces FIT and FICA
  taxable wages up to the monthly limit, the excess is withheld after tax)
- Add a taxable fringe benefit (WFH stipend — increases gross and all taxable wages)
- Read base-regulation case fields and lookups from an L2 script
- Number L2 deductions so they are included in net pay
- Keep a company policy value in an L2 data regulation and document its source with a `.lex` manifest

---

## The Customizations

| Customization | WT | Collector | Federal treatment | State treatment |
|:---|:---:|:---|:---|:---|
| **§132(f) Transit — up to the limit** | 1250 | `US.EmployeeDeductions` | FIT + FICA exempt | Per state wage base of US.Payroll (lookup `StateTaxableWageBase`): excluded in most states incl. NY, CT and CA; taxable in NJ, PA and MS |
| **§132(f) Transit — excess** | 5520 | `US.EmployeeDeductions` | Taxable, post-tax deduction | Taxable |
| **WFH Equipment Stipend** | 1260 | `US.GrossWages` | Fully taxable | Taxable |

`Apex.TransitBenefitMonthly` is the employee's **monthly** election. The script caps it at the
2026 monthly limit of $340 (lookup `US.FederalTaxParameters`, key `TransitMonthlyLimit`) and
converts both parts to the pay period: monthly × 12 / periods per year.

The WFH stipend is capped at the company policy maximum of $200 per pay period (lookup
`Apex.PolicyParameters`, key `WFHStipendMaxPerPeriod`, regulation `Apex.Payroll.Data.Policy`).

---

## Source-Traced Company Policy (`.lex`)

The $340 transit limit is a statutory value and lives in the licensed US.Payroll data
regulations. The $200 stipend maximum is different: it is a **company policy**. Apex keeps it in its own
data regulation `Apex.Payroll.Data.Policy` (`Data.Policy.2026/`) and documents where it comes from:

```
Data.Policy.2026/
  Regulation/Apex.Payroll.Data.Policy.2026.json   the lookup Apex.PolicyParameters (one value)
  .lex/
    lex.json                                      source manifest (maintained manually)
    Apex-EmployeeHandbook-2026-Excerpt.md         evidence document
    snapshot.json                                 generated by LexSnapshot (immutable)
```

| Rule | Why |
|:---|:---|
| One lex entry per lookup value (`Apex.PolicyParameters.WFHStipendMaxPerPeriod`) | The manifest must cover every value of the data regulation |
| The value in `lex.json` is the value in the regulation JSON | The lex entry is the source; the regulation takes the value from it |
| `sourceLocation` names the handbook section; `legalReference` states that no statute applies | A company policy has an internal source, not a legal norm |
| The evidence document sits in `.lex` and is declared in `files[]` (`documentRef`) | The snapshot is self-contained and survives changes of the intranet page |

Create or refresh the snapshot (offline, no backend or license needed):

```bash
cd Data.Policy.2026/.lex
pecmd LexSnapshot lex.json /dryrun     # validate only
pecmd LexSnapshot lex.json             # write snapshot.json
```

`snapshot.json` is skipped when it already exists. To re-create it after a policy change, delete it first.

---

## Design Notes

| Rule | Why |
|:---|:---|
| `Apex.Payroll` has **no namespace**; all objects carry the `Apex.` prefix in their name | Scripts of a regulation with a namespace prefix every case field and lookup name with that namespace. With namespace `Apex`, `US.WorkState` would resolve to `Apex.US.WorkState` and fail. |
| Base lookups are addressed with their full name (`US.FederalTaxParameters`) | The US data regulations use namespace `US`; the stored lookup name includes it. |
| Employee deductions are numbered **below 6500** (WT 1250, 5520) | NetPay (WT 6500) reads the `US.EmployeeDeductions` collector, which only contains wage types processed before it. A deduction numbered above 6500 would be missing from net pay. |
| Employer-only wage types may use numbers above 6900 | They do not affect net pay. |

## Run

```bash
pecmd Customize.pecmd
```

The script runs five imports:

```bash
# Step 1: Import the L2 regulation
pecmd PayrollImport Apex.Payroll.2026.json

# Step 2: Import the company policy data regulation
pecmd PayrollImport Data.Policy.2026/Regulation/Apex.Payroll.Data.Policy.2026.json

# Step 3: Link both L2 regulations to all payrolls
pecmd PayrollImport PayrollsWithL2.json

# Step 4: Set transit elections for NYC employees
pecmd PayrollImport CaseValues/TransitBenefit-NYC.json

# Step 5: Set WFH stipend for remote employees
pecmd PayrollImport CaseValues/WFHStipend-Remote.json
```

## Files

| File | Description |
|:---|:---|
| `Apex.Payroll.2026.json` | L2 regulation: case `Apex.Benefits`, WT 1250 / 1260 / 5520, script `Apex.WageTypeValueFunction` |
| `Data.Policy.2026/Regulation/Apex.Payroll.Data.Policy.2026.json` | L2 data regulation: lookup `Apex.PolicyParameters` (WFH stipend maximum) |
| `Data.Policy.2026/.lex/` | Source manifest `lex.json`, evidence document, generated `snapshot.json` |
| `PayrollsWithL2.json` | Updated payroll layers (adds both L2 regulations to all 3 payrolls) |
| `CaseValues/TransitBenefit-NYC.json` | Monthly transit elections: Sara $315, Carlos $400 (above the limit), Linda $315 |
| `CaseValues/WFHStipend-Remote.json` | $200 per period for Kevin, Jessica |
